# HanaV Stock Analyzer v1.2

국내 주식 **한 종목 집중 분석**용 Streamlit 웹앱입니다. KOSPI/KOSDAQ 6자리 코드로 검색할 수 있으며, 시세·기술지표·영업이익 추이·간이 재무건전성·외국인/기관 수급·뉴스·DART 공시를 표시하고 **근거 기반 100점 종합 평가**를 계산합니다.

> **정확성 안내**: 종합 점수는 미래 수익률, 투자 권고, 적정주가가 아닙니다. 일부 항목은 업종 상대평가가 미반영된 v1.0 초기형 휴리스틱입니다. 데이터 공급처 장애·키 부재 시 해당 영역은 **미산출**되며, 가용 항목의 점수만 재가중합니다. 충족률이 낮은 점수는 종목 간 비교하면 안 됩니다.

## 바로 실행하기 (Windows)

1. ZIP 파일을 압축 해제합니다.
2. 폴더 안에서 터미널(PowerShell) 실행:

```powershell
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
streamlit run app.py
```

Python 3.11/3.12 권장. 브라우저에서 보통 `http://localhost:8501`로 열립니다.

## Streamlit Community Cloud 배포

1. 프로젝트 폴더 내용(`app.py`, `data_sources.py`, `scoring.py`, `report.py`, `requirements.txt`, `.streamlit/config.toml` 등)을 **본인 GitHub 저장소** 루트에 업로드합니다. 기존 앱 저장소와 혼동하지 않도록 별도 저장소를 권장합니다.
2. [share.streamlit.io](https://share.streamlit.io/)에서 **Create app** → GitHub 저장소 선택 → Main file: `app.py` → Deploy.
3. Streamlit Cloud **App settings > Secrets**에 필요한 인증정보를 등록합니다. OpenDART와 KIS 인증키는 화면에 입력하지 않으며 서버 측 Secrets에서만 읽습니다.

```toml
DART_API_KEY = "본인_OpenDART_인증키"
KIS_APP_KEY = ""
KIS_APP_SECRET = ""
```

DART·KIS 인증정보는 **서버 측에서만 사용**됩니다. KRX 조회는 현재 별도 KRX 키 없이 `pykrx`를 활용하며, Supabase는 이 버전에 연동되지 않았습니다. `secrets.toml` 원본은 GitHub에 절대 올리지 마세요. 이 버전은 OpenAI 키 입력·호출 기능을 제거했으며 종합 의견과 이벤트 평가는 별도 생성형 AI 비용 없이 규칙 기반으로 계산됩니다.

## 처음 사용하는 순서

1. 기본 `005930` 삼성전자를 열어 봅니다. 종목코드 `000660` (SK하이닉스), `035420`(NAVER) 등도 지원합니다.
2. 6자리 코드로는 모든 종목을 직접 조회할 수 있습니다(데이터 제공처가 해당 종목을 제공해야 합니다). **종목명 검색 범위**를 넓히려면 사이드바에서 `KRX 전체 종목 목록 불러오기` 또는 DART 키 설정 후 `DART 상장사 목록 불러오기`를 누르세요.
3. OpenDART 키 없이도 **주가/차트/기술분석/뉴스** 등 공개 접근 가능한 데이터부터 표시합니다. 재무/공시를 사용하려면 [OpenDART 개발자](https://opendart.fss.or.kr/)에서 발급한 인증키를 Streamlit Secrets의 `DART_API_KEY`에 설정하세요. DART·KIS 키 입력창은 화면에 표시되지 않습니다.
4. KIS App Key/Secret이 있다면 **KIS REST 조회 시점 현재가**를 추가로 표시할 수 있습니다. 실시간 WebSocket 스트리밍은 포함하지 않습니다. 실전투자용 키의 접근 권한 및 데이터 재배포 가능 여부는 별도로 확인하세요.
5. 재무 항목과 성장률은 DART 확정 실적 기준이며, **영업이익 시나리오**는 사용자가 가정한 성장률 민감도일 뿐 컨센서스가 아닙니다.
6. `리포트·기록` 탭에서 **인쇄용 HTML**, 평가표 CSV, 점수 스냅샷 JSON을 다운로드할 수 있습니다. HTML을 브라우저에서 열고 인쇄 → PDF 저장이 가능합니다. 이전 JSON을 업로드해 점수 변화도 비교할 수 있습니다.

## 데이터 및 점수 평가 원칙

| 구성 | 연결 방식 | 제한 |
| --- | --- | --- |
| 일봉/종가 | Yahoo Finance → FinanceDataReader 대체 | 공급처 지연/변경에 따라 빈 값 가능; 조정 전 OHLC |
| REST 시세(선택) | KIS OpenAPI `inquire-price` | 본인 App Key·Secret, 조회 시점 스냅샷이며 스트리밍 아님 |
| 확정 재무제표 | OpenDART `fnlttSinglAcnt` | 사용자 인증키 필요; 연결재무제표 우선, 없으면 별도재무제표(혼합 금지) |
| 외국인/기관 수급 | KRX / pykrx | 외부 KRX 엔드포인트 정책 변경 시 일시 중단 가능 |
| 뉴스·이벤트 | OpenDART 주요 공시 제목(6점) + Google News RSS 독립 출처의 최근 21일 제목(4점) | 본문·재무 영향 미확인; 점수 신뢰도 낮음 |
| 공시 | OpenDART `list.json` | 최근 95일, 사용자 인증키 필요 |
| PER/PBR 등 | Yahoo Finance 정보 API | 값의 기준일/정확성이 공시와 다를 수 있음 |
| 자동 종합 의견 | 로컬 규칙 기반 평가 엔진 | 추가 OpenAI 인증키 및 API 호출 비용 없음 |

**배점**: 성장성 25 / 가치평가 20 / 수급 15 / 재무건전성 20 / 주가 추세 10 / 뉴스 10 (총 100). 가치평가 20점은 **KRX 업종 PER 상대비교 6점, 과거 5년 PER·PBR 밴드 5점(PER 3 + PBR 2), 3개년 ROE 지속성 5점, 동일 전망기간 Forward PER 업종비교 4점**으로 세분화됩니다. 실제 산출되는 가치평가 세부 항목만 가중평균에 넣고, 누락된 항목은 0점이나 50점으로 대체하지 않습니다. 충족률은 **평가된 세부 배점 합계**를 반영하므로 가치평가 20점 중 6점만 검증되면 전체 충족률에는 6%p만 더합니다. 다른 영역의 내부 세부지표 누락 여부는 아직 완전히 반영하지 못하므로 충족률을 전체 자료의 정확도나 예측 확률로 해석하지 마세요.

**한계(중요)**

- 수급은 외국인+기관 순매수를 **동일 날짜의 종목 거래대금(5일 4점·20일 5점)** 및 **20일 말 시가총액(4점)**으로 정규화하고, **최근 10거래일 매수 지속성(2점)**을 별도로 반영합니다. KRX 공식 일별 거래대금 우선, 미수신 시 일별 종가×거래량으로 근사하며 출처를 표시합니다. 필요한 날짜·수급 자료가 없으면 해당 배점만 미산출 처리합니다. 공매도·프로그램 매매의 별도 해석은 하지 않습니다.
- 가치평가는 동종업종 상대비교와 과거 5년 PER·PBR 밴드를 활용합니다. 공개데이터 연결 및 분류·회계 기준의 한계가 있으므로 `적정주가`나 확정적 저평가 판정으로 해석하지 마세요.
- 금융업은 일반 제조업 부채비율 점수에서 제외하지만 은행/보험 고유 건전성 지표를 넣기 전까지 제한이 있습니다.
- 뉴스 모멘텀은 최근 60일 공식 공시의 명확한 이벤트(6점)와 최근 21일 서로 다른 매체 2곳 이상에서 확인된 이벤트성 뉴스 제목(4점)으로 분리합니다. 공시·기사의 내용, 사건 규모, 반어·오보·수정 여부를 자동 검증하지 못하므로 낮은 신뢰도로 표시합니다. 공식 공시와 중복되는 뉴스 범주는 중복 채점하지 않습니다.
- 4분기 손익은 **연간 확정값 – 3분기 누적값**으로 생성 가능한 경우만 표시합니다. DART 분기 IS의 `thstrm_amount`는 해당 3개월, `thstrm_add_amount`는 누적입니다. 재무제표 제출·수정 시점이 다를 수 있습니다.
- 당기순이익/부채비율/시총 등의 단순 계산은 특정 업종에서 충분하지 않을 수 있고, 주가 성과에 대한 통계적 검증(백테스트)은 수행하지 않았습니다.
- 외부 고객 공유·유료 서비스에 활용하기 전에 **시세·재무정보·뉴스의 재배포 라이선스와 사내 준법 검토**가 필요합니다.

## 오류 해결

- **주가가 안 나와요** → Yahoo 또는 FinanceDataReader 외부 데이터 제공처가 막혔을 수 있습니다. 다른 종목을 시도하거나 30분 후 새로고침하세요. 회사 네트워크 정책상 외부 시세 접근이 막힐 수 있습니다.
- **종목명이 안 찾아져요** → 6자리 코드로 검색하거나 `KRX 전체 종목 목록 불러오기`를 누르세요.
- **재무가 없어요** → OpenDART 키를 넣었는지 확인하세요. 보고서 미제출·회사별 계정표 차이·정정 공시의 경우 빈값이 정상일 수 있습니다.
- **수급이 없어요** → KRX 외부 API 접속 제한/스키마 변경 가능성이 있습니다. 다른 영역 분석은 계속 작동합니다.
- **OpenAI 키 입력칸이 안 보여요** → 정상입니다. 불필요한 별도 비용을 막기 위해 AI 입력칸과 유료 호출 버튼을 제거했습니다.

### DART 재무 분석이 비어 있을 때

Streamlit 앱 왼쪽 **DART 연결 진단**을 열고 **DART 연결 진단 실행**을 누르세요.

- **상태 정상**: 기업개황 인증 성공 및 삼성전자 2024년 연간 재무 응답이 확인된 상태입니다. 그래도 항목이 비어 있으면 **새로고침(캐시 초기화)**을 누른 뒤 재조회하세요.
- **010/011**: 인증키가 미등록이거나 정지된 상태입니다.
- **012**: DART에서 앱 서버 IP 접근을 허용하지 않은 상태입니다.
- **020**: OpenDART 요청 한도를 초과한 상태입니다.
- **통신 오류/시간 초과**: 네트워크 혹은 서버에서 DART 접근 실패 가능성이 있습니다.

DART·한국투자증권 KIS 인증키는 서버 측 Secrets로만 읽습니다. 이 버전에는 OpenAI 클라이언트·호출 버튼이 없으며, 과거에 등록한 `OPENAI_API_KEY`도 앱에서 사용하지 않습니다.

데이터 충족률이 50% 미만이면 종합 의견을 **판단 보류**로 표시합니다. 잠정 점수는 결측 데이터가 있는 상태에서 정규화된 참고치이며, 완전한 100점 평가로 해석할 수 없습니다.


## 최근 애널리스트 리포트 (2026-11-06 추가)

앱의 **📑 애널리스트 리포트** 탭에서 검색한 국내주식의 증권사 기업분석 보고서 메타정보를 조회합니다.

- 조회 범위: 최근 6개월, 발행일 최신순, 최대 18건
- 표기 항목: 리포트 제목, 발행일, 증권사, 애널리스트, 목표주가(제공처에 있을 때만)
- **리포트 제목을 클릭**하면 원문 제공처의 보고서 또는 PDF를 새 창에서 엽니다.
- 우선 소스: Npay 증권 공개 리서치 v2 목록(종목코드 기반, 최대 10건/요청). 해당 API에서 결과가 비어 있거나 오류가 나면 모바일 종목요약의 `researches` 목록(`id`/`tit`/`bnm`/`wdt`)을 시도합니다. 마지막으로 한경 컨센서스 공개 리포트 목록을 조회합니다. 각 출처의 비공식 API 접근 조건·이용약관과 상업적 활용 권한을 별도로 확인해야 합니다.
- Npay 응답은 `nid`로 식별되는 원문 리포트 페이지로 링크하고, 한경은 게시자가 제공하는 링크를 사용합니다. 제목·발행일·증권사·목표주가 등은 제공처에서 실제 수신된 정보만 표시합니다.
- 자동 수집이 실패하면 선택 종목의 `https://stock.naver.com/domestic/stock/{종목코드}/research` 페이지와 한경 컨센서스를 직접 열 수 있습니다. API 응답 형식·접근 제한 정책이 변경되면 자동 목록이 비어 있을 수 있습니다.
- PDF 전체 텍스트, 원문 파일은 앱에 내려받거나 복제하지 않습니다. 애널리스트 의견 및 목표주가는 보고서 발행 당시의 견해입니다.
- 해당 목록은 현재 100점 평가에 별도 점수로 반영되지 않습니다. 발행처의 데이터 라이선스를 준수합니다.


## 밸류에이션 대체 연동 (2026-11-06)

기존 Yahoo Finance의 `trailingPE`·`priceToBook`가 비어 있으면 다음 순서로 대체 데이터를 사용합니다.

1. **한국투자증권 KIS REST 현재가 API**가 연결되어 있으면 그 응답의 `per`·`pbr` 지표를 사용합니다(`KIS_APP_KEY`·`KIS_APP_SECRET` 필요).
2. 제공처 지표가 빠지면 **KRX OPEN API의 유가증권/코스닥 일별매매정보**에서 보통주 및 확인된 우선주 시가총액을 조회합니다. DART에서 확정된 최근 연간 순이익·자본으로 `시가총액 / 순이익`(간이 PER), `시가총액 / 자본총계`(간이 PBR)을 산출합니다. 재무정보가 최신이거나 손익이 적정할 때만 해당 항목을 계산하며, 원천과 사업연도·거래일을 함께 표기합니다.
3. 지배주주 귀속분과 비지배지분, 최근 4개 분기(TTM), 자기주식·주식종류·우선주 시장가액 등 차이 때문에 **간이 PER·PBR은 공식 PER·PBR이나 동일 기준 컨센서스가 아닙니다.** 업종별 보정도 없어 계산된 가치평가 점수는 낮은 신뢰도로 표시합니다.
4. 연결 불가·미승인·확정재무 결측 시에는 숫자를 임의로 만들지 않고 미산출 처리하며, 밸류에이션 탭에서 KRX 오류 원인을 표시합니다.

KRX는 **인증키 발급뿐 아니라 주식 일별매매정보 API에 대한 별도 활용신청/승인**이 필요합니다. Streamlit Cloud Secrets에는 다음 중 하나를 등록하세요.

```toml
KRX_API_KEY = "발급받은_KRX_OPEN_API_인증키"
```

추가로 `KRX_AUTH_KEY`, `KRX_OPEN_API_KEY`, `KRX_OPENAPI_KEY`, `KRX_KEY`, `AUTH_KEY` 이름도 호환됩니다. 인증키는 서버에서만 읽고 HTML에는 전달하지 않습니다.

KRX OPEN API는 개인 연구 등 비상업 목적 제한과 출처 표기·재배포 금지 조건이 있으므로, **고객 제공·유료 서비스나 공개 앱 운영 전에 사용 권한을 별도로 확인**해야 합니다. 출처: 한국거래소 통계정보. 주식 종목 일부에 KRX 최신 응답이 없으면 조회 시점에 따라 여러 거래일을 역탐색합니다.


## 가치평가 2.0: 실제 비교자료 기반 · 미확보 항목 보류

- **동종업종 PER 6점**: `pykrx`가 반환하는 한국거래소 업종분류(넓은 업종)와 같은 날짜의 PER. 비교기업 최소 5개 필요. 단순 절대 PER 기준표는 제거했습니다.
- **과거 밴드 5점**: 종목별 약 5년 월말 PER(3점)과 PBR(2점)을 각각 과거 상대분위로 평가. 유효 월 24개 이상, 기간 3년 이상일 때만 점수 산정. 낮은 과거 분위일수록 높은 점수이지만 구조적 저성장·감익 리스크는 별도로 검토해야 합니다.
- **3개년 ROE 지속성 5점**: 최근 3개 연속 사업연도의 DART 순이익/기말 자본으로 간이 ROE를 구해 중앙값·흑자 연차 수·연도별 변동성을 평가합니다. KRX PBR은 별도 참고정보로 표시하지만 PBR/ROE로 PER을 다시 계산하지 않습니다. 이익과 자본이 모두 확인되는 최근 3개년이 없으면 5점 배점을 미산출 처리합니다.
- **동일기간 Forward PER 4점**: 동종업종 3개 이상에 대해 **동일한 전망기간**의 비교 가능한 컨센서스 PER 데이터가 있을 때만 산출. 현재 공개형 기본 설정은 비교가능 컨센서스 피드를 제공하지 않으므로 **4점은 미산출**이 정상입니다. 종목의 `forwardPE` 하나만으로 저평가라고 판단하지 않습니다.
- **재무건전성 20점**: 부채비율(5), 영업현금흐름/영업이익(6), 영업이익/이자비용(5), 유동자산/유동부채(4)를 분리해 평가합니다. 첫 항목은 DART 주요계정, 나머지는 DART 전체 재무제표(`fnlttSinglAcntAll`, 동일 사업연도·연결/별도 구분)에서 조회한 **확인된 정보만 반영**합니다. 모든 세부 정보가 없으면 확인한 배점만 합산합니다. 금융업(은행/증권/보험 등)은 별도 감독 기준이 필요하므로 산업 일반기준으로 점수를 계산하지 않습니다.

실제 시장 데이터가 누락·차단되거나 제공처 인터페이스가 달라지면 일부 항목은 미산출됩니다. `pykrx`의 KRX 공개사이트 조회는 KRX OPEN API 인증키와 **별개의 경로**이며, 같은 주식 정보를 제공한다는 이유로 이용권한이 자동 확보되는 것은 아닙니다. 사용권 확인 및 데이터 사용범위 준수가 필요합니다. 앱은 대체 값을 임의로 생성하지 않습니다.
